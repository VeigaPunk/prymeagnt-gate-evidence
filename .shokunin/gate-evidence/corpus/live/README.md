# Live read-only Git whitespace-gate audit (round 4)

From the repository root, run `python3 .shokunin/gate-evidence/corpus/live/audit_gate.py --revision <commit>` against a real existing commit with changed files. The command inspects the commit delta with `git diff --check <commit>^ <commit>` and injects a trailing-space line **via stdin**, without changing the worktree, into an independent `git diff --no-index --check /dev/null /dev/stdin` negative control. The script captures actual process exit codes, stdout, stderr, executable and environment values in JSON; its own exit 0 means the chosen commit had changed files, the positive gate passed, and the negative control failed with a whitespace diagnosis. It does not establish goal completion, inspect the active mission goal, run autonomous mode, mutate gate configuration, or call `goal.complete()`.

A repeat auditor should compare captured exits and diagnostics against a separate native invocation, e.g. `git diff --check <commit>^ <commit>` and `printf 'bad trailing space \n' | git diff --no-index --check /dev/null /dev/stdin`; nonzero negative-control exit is the expected *gate failure*, not an audit failure. The two commands have different inputs: a passing project commit does not imply all project commits pass. `git diff --check` checks whitespace errors in patches, not test or acceptance success. Policy basis for keeping candidate gate, goal status, and stop state separate: `skills/ufo/references/run-logic.md:443-455,512-524`; `docs/ufo-workflow.md:50-63,202-215`.
